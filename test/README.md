# 图片提问与参考图验收

自动检查：`npm test`、`npm run build`。

浏览器验收使用 [fixtures/reference-circle.png](fixtures/reference-circle.png)，不需要私人照片：

1. 普通对话点击“上传图片提问”选择该文件，确认仍显示“发送”和聊天模型，图片缩略图、预览和移除可用。仅添加图片也应允许发送，使用默认描述问题。
2. 检查多选/粘贴与最多三张的提示，以及损坏图片和大于 10 MiB 文件的错误。选择图片时不应发起上传请求。
3. 在手机尺寸下确认输入区无横向溢出、图片和发送按钮可访问。切换图片生成再退出时待发图片保留，新建对话清空图片。
4. 在线上提问“图片里的形状和颜色是什么？”，确认回答包含橙色圆形，成功后附件区清空，消息中的图片仍可预览。再问“它的背景是什么颜色？”，确认仍能看到原图上下文。两种中文模型均支持看图；等待回复时新输入的文字不能被清空。此步骤调用 DeepSeek，使用合成测试图，不上传私人照片。
5. 对失败路径使用本地未配置服务或不可用测试接口：失败后问题和附件保留；重试时失败的上一条用户消息不重复发送。超过图片或上下文上限应明确提示新建对话。
6. 选择“图片生成”后，附件标题应变成“参考图”，比例/分辨率选项可用。必要时在线上提交“保持参考图的圆形主体和构图，将橙色圆改成蓝色，背景保持米白色，不要文字。”使用 1:1、1K。此步骤会消耗一次生图额度，仅在生成接口修改需要验收时运行。
7. 生图应先上传参考图再创建任务，完成后显示可预览、可下载的结果；失败时保留描述和参考图。普通看图对话应只请求聊天接口，不调用上传或生图接口。

上传与任务请求可通过浏览器网络面板检查。不要记录或提交 API Key，服务端调试也只输出必要的错误结构。

## 文档工作区验收

1. 从「工作台」或首页「工作」进入，新建空白文档或模板；改名并编辑含中文标题、列表和表格的内容，确认预览和保存状态正确。
2. 插入 `fixtures/reference-circle.png`，预览中应显示图片；刷新后重新打开「我的文档」，正文、图片和纸张设置应保留。
3. 使用 `fixtures/workspace-sample.md` 检查四种导出。PDF/Word 必须打开后阅读，确认中文、长英文、图片、表格和任务列表；长表格跨页重复表头，标题不要孤立在页尾。PDF 中文应可选中复制；Word 应保留可编辑结构。MD 内嵌本地图片，TXT 不包含 Base64。
4. 在 390 × 844 手机尺寸检查编辑 / 预览、文档列表、文件名与格式选择；页面无横向溢出，底部导出按钮可访问。
5. 用合成内容测试真实 AI 起草或修改：建议出现后原稿不变，应用后内容更新，撤销可恢复。选中文字修改只替换选区。生成期间手动改正文时禁止应用旧建议；切换文档或返回对话应取消生成，不能弹出隐藏工作区的对话框。
6. 本地未配置 API 时测试失败路径，确认指令和正文保留。存储失败与重试通过 `documentStore.test.js` 的 IndexedDB 测试覆盖；`requestDocument` 的长文分块和截断输出通过 API/Worker 测试覆盖。
7. 测试「对话转文档 → 编辑 → 导出」完整流程，确认返回对话后已有消息仍在。不要在验收中删除用户原有草稿，仅使用明确命名的测试文档。

导出排版 QA 应使用 Codex 捆绑的 LibreOffice 与 Poppler。中文字体可通过临时 Fontconfig 配置将 `public/fonts` 提供给渲染进程，不需要修改系统字体或安装桌面办公软件。生成的 QA 文档及渲染图保存在临时目录，不提交到仓库。
